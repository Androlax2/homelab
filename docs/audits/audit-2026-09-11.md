# Audit — 2026-09-11

Scope: maintainability of the whole repo (stacks, Glance config, scripts, tests, CI). A security review was done
at the same time; its report is intentionally not committed because this repository is public.

## Executive summary

The repo is in good shape for a single-owner homelab: one stack per folder, pinned images, secrets kept out of git
behind an enforced `.env.example` contract, and deploy tooling covered by tests that run the scripts through their
real entry points. The one thing to fix first is `scripts/cleanup_deluge.sh`: its name-prefix fallback can match
the wrong torrent and delete that torrent's data. After that, the biggest drag on future work is configuration
that lives outside the repo or is repeated in several places (shared env values, service ports, a duplicated
449-line Glance template), plus a few services the dashboard knows about but the repo does not.

## Findings

### [P1] `cleanup_deluge.sh` can delete the wrong torrent
- **Where**: `scripts/cleanup_deluge.sh:107-116` (`find_torrent_hash`, prefix fallback)
- **What**: when no torrent has exactly the orphan's folder or file name, the fallback accepts any torrent whose
  name starts with the candidate (or the reverse) and returns the first one. An orphan is, by definition, a file
  whose own torrent is usually gone, so the fallback runs in the common case. Example: orphan
  `/downloads/Dune/Dune.mkv`, active torrent `Dune.Part.Two.2024.2160p...` → the script runs
  `rm <Dune Part Two hash> --remove_data`.
- **Why it matters**: irreversible deletion of an unrelated download. Library copies survive when they are
  hardlinks, but anything not imported yet is lost, and seeding stops.
- **Suggested fix**: drop the prefix fallback (exact match only; unmatched orphans already go through the
  `PURGE_UNMATCHED` path, which deletes only the orphan file itself), or accept a prefix match only when it is
  unique and log it. Add the Dune case to `scripts/tests/cleanup_deluge_test.sh` as a regression test. Effort S.

### [P2] Services and variables that live outside the repo
- **Where**: `config/glance/config/widgets/services-monitor.yml:15-17` (Kimai), `config/glance/config/widgets/releases.yml:9,15,19`
  (AdGuard Home, Uptime Kuma, Kimai), `stacks/infrastructure/.env.example:9-10,22-23`
  (`SERVER_ID`, `TAILSCALE_AUTHKEY`, `SYNOLOGY_NAS_PASSWORD`, `ADGUARD_HOME_PASSWORD`, used by no file in the repo)
- **What**: the dashboard and the env contract reference services that no stack defines.
- **Why it matters**: the repo is meant to be the full description of the server. Anything outside it is not
  updated by Renovate, not deployed by `deploy.sh`, and forgotten when the server is rebuilt. The unused keys are
  also passed to the Glance container through `env_file: .env`.
- **Suggested fix**: per service, either add a stack or drop the references; remove the unused keys from
  `.env.example` and from the server's `.env`. Effort S–M.

### [P2] The same values are repeated in every stack's `.env`
- **Where**: `DOCKERCONFDIR`, `DOCKERLOGGING_MAXFILE`, `DOCKERLOGGING_MAXSIZE`, `TZ`, `PUID`, `PGID`, `LAN_IP` in
  most `stacks/*/.env.example`
- **What**: each stack's `.env` must hold its own copy of the server-wide values.
- **Why it matters**: changing the time zone or the log size means editing up to six `.env` files on the server,
  and a stack that is missed drifts silently.
- **Suggested fix**: a gitignored `stacks/common.env` passed before the stack's own file
  (`docker compose --env-file stacks/common.env --env-file stacks/<stack>/.env ...`) in `deploy.sh`,
  `edit_env.sh` and `check_stacks.sh`, plus in `env_file:` where containers need those values. Check first that
  the server's Compose version accepts several `--env-file` flags. Effort M.

### [P2] `.env.example` gives no hint about the expected format
- **Where**: all `stacks/*/.env.example`; consumers such as `config/glance/config/widgets/arr-releases.yml:15`
  and `media-monitor.yml:14` (prepend `http://`, so `*_URL` must be `host:port`), `stacks/security/.env.example`
  (`VAULTWARDEN_DOMAIN` must be the full public URL)
- **What**: keys are listed with empty values and no explanation.
- **Why it matters**: a wrong format fails quietly (an empty widget, a broken login link) months later when you
  add a stack or rebuild the server.
- **Suggested fix**: one comment line above each non-obvious key (`env_keys` in `scripts/lib.sh` ignores
  comments). Effort S.

### [P2] A 449-line Glance template exists twice
- **Where**: `config/glance/config/widgets/arr-releases.yml` and `arr-releases-sonarr.yml` (line 1 of each:
  "keep in sync")
- **What**: the Radarr and Sonarr widgets carry identical templates.
- **Why it matters**: every fix has to be made twice; the files will drift.
- **Suggested fix**: one widget file holding both entries, sharing the template through a YAML anchor
  (`template: &arr-releases |` then `template: *arr-releases`), included once from `pages/medias.yml`. Glance's
  `$include` is textual, so the anchor stays inside a single file. Effort S.

### [P2] Nothing validates `config/` before it is deployed
- **Where**: `scripts/check_stacks.sh` (compose files only), `scripts/deploy.sh` (restarts the container on any
  `config/<name>/` change)
- **What**: a YAML mistake in `config/glance` passes CI and is restarted straight into the dashboard.
- **Why it matters**: the dashboard goes down on a typo, and you only notice when you open it.
- **Suggested fix**: in CI, load `config/glance` with the pinned Glance image if it offers a config check (verify
  its CLI), or at minimum parse every YAML file. Note that `pages/*.yml` repeat the `$include` key inside one
  mapping, which strict YAML parsers reject. Effort M.

### [P3] Log rotation is configured two different ways
- **Where**: `x-logging` anchor in `stacks/media/compose.yml:1` and `stacks/opusline/compose.yml:8`; inline copies
  in `stacks/infrastructure/compose.yml:13,48`, `stacks/photos/compose.yml:15,49,67`,
  `stacks/portainer/compose.yml:12`, `stacks/security/compose.yml:12`
- **Suggested fix**: use the anchor everywhere. Effort S.

### [P3] LinuxServer images come from two registries
- **Where**: `lscr.io/linuxserver/*` (tautulli, prowlarr) vs Docker Hub `linuxserver/*` (sonarr, radarr) in
  `stacks/media/compose.yml`; `renovate.json` has to list both forms
- **Suggested fix**: use `lscr.io` for all four and simplify the Renovate rule. Effort S.

### [P3] Settings that do nothing, and a stale comment
- **Where**: `PUID`/`PGID` passed to images that ignore them (`stacks/media/compose.yml:148-149` Postgres,
  `stacks/photos/compose.yml:21-22,46-47,73-74` Immich); Seerr sets both `user:` and `PUID`/`PGID`
  (`stacks/media/compose.yml:49,60-61`); the Plex `devices` comment says "uncomment this line" on an active line
  (`stacks/media/compose.yml:217-218`)
- **Why it matters**: they suggest those containers run as your user, which they don't.
- **Suggested fix**: delete them. Effort S.

### [P3] Service ports are written in three places
- **Where**: compose `ports`/host-network defaults, `glance.url` labels, and the monitor widgets
  (`config/glance/config/widgets/services-monitor.yml`, `media-monitor.yml`)
- **Why it matters**: moving a port takes three edits.
- **Suggested fix**: accept it knowingly, or drop monitor entries that the label-driven `docker-containers` widget
  already covers. Effort S.

### [P3] Wrong variable names in an error message
- **Where**: `config/glance/config/widgets/prowlarr-indexers.yml:26,29` mention `PROWLARR_API_URL` and
  `PROWLARR_KEY`, which don't exist (the widget reads `PROWLARR_URL` and `PROWLARR_API_KEY`)
- **Suggested fix**: fix the text. Effort S.

### [P3] `OPUSLINE_VERSION` is an invisible setting
- **Where**: `stacks/opusline/compose.yml:15,41`; absent from `stacks/opusline/.env.example`
- **What**: `${OPUSLINE_VERSION:-latest}` silently floats to `latest` when unset, and the default also hides it
  from `check_stacks.sh` (Compose doesn't warn about variables that have a default).
- **Suggested fix**: list it in `.env.example`, and decide whether an unset value should fail instead
  (`${OPUSLINE_VERSION:?}`). Effort S.

## Aligned-and-healthy

Protect these as the repo grows:

- One folder per stack, one Compose project per folder, `container_name` on every service.
- `config/<name>/` belongs to the container `<name>`: no lookup table between deploy logic and folders.
- Secrets only in gitignored `.env` files; `.env.example` is the contract, enforced by `check_stacks.sh` (CI),
  `deploy.sh` and `edit_env.sh`.
- Images pinned to exact versions (Immich's database by digest), with Renovate rules for the unusual tag formats.
- `deploy.sh` fails loud and never tears anything down by itself; a failed run is retried.
- Scripts use `set -euo pipefail` and are tested through their real entry points with stubbed `docker`/`curl`.
- `stacks/opusline/compose.yml`: healthchecks, `depends_on: service_healthy` and anchors, the model for new stacks.
